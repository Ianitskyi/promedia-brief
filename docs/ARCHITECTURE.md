# Архітектура BRIEF 0.2

Принцип: **система не пише новин — вона відбирає, атрибутує й озвучує тексти джерел, а редактор затверджує.** Генеративна модель (Gemini чи інша) у конвеєрі не використовується.

```
RSS (18 медіа Білого списку ІМІ + 125 фідів Мапи рекомендованих медіа)
  └─ brief collect      → data/raw/<дата Києва>.json      щогодини, злиття, retry
       └─ brief draft   → editions/<дата>/draft.json|md   щодня, без TTS
            нормалізація → дедуплікація → кластери → теми/регіон → importance score
            → екстрактивний сценарій → трасування фактів
       └─ review.html   редактор: правка, виключення, підтвердження ⚠, sha256
       └─ brief approve → approved.json   (повторні перевірки; хто й який саме текст)
       └─ brief render  → editions/<дата>/audio/*.mp3, render.json   (TTS + монтаж)
       └─ brief verify-audio  (необов'язково: ASR-звірка аудіо з текстом)
       └─ brief publish → edition.json, latest.json   (fail closed)
  └─ index.html читає editions/latest.json і збирає плейлист під слухача
```

| Етап | Вхід | Вихід | Помилки |
|---|---|---|---|
| collect | `config/sources.json`, `config/media_map.json` | `data/raw/<дата>.json` (злиття) | Збій одного фіду логуються в `errors`, решта працює; job падає лише якщо впали всі. Тимчасові помилки (5xx, 429, мережа) — 3 повтори з backoff; 403/404 не повторюються й не обходяться |
| draft | пули за дату й попередню | `draft.json`, `draft.md`, `drafts.json` | Сюжет без придатного заголовка, з непідтвердженими твердженнями або можливий дубль — пропускається й потрапляє в журнал |
| approve | відредагований `draft.json` | `approved.json` | Будь-яке ✗ або непідтверджене ⚠, відсутнє розкриття джерел у вступі, змінений sha256 → відмова |
| render | `approved.json` | аудіо + `render.json` | sha256 перевіряється; платний TTS без дозволу → відмова; збій посередині → наступний запуск продовжує з кешу |
| publish | `approved.json` + `render.json` | `edition.json`, `latest.json`, `audio/daily.mp3` | Будь-яка невідповідність (інший текст, бракує сегмента, mock-аудіо, ASR-прапорці) → нічого не записується |

## Ключові рішення

**Екстрактивний сценарій.** Сюжет = «<Видання> повідомляє: <заголовок>.» + до одного речення анотації, що додає інформацію. Інші видання, що повідомили про подію, в ефірі не перелічуються (рішення 21.10.2026) — вони є на сайті під сюжетом; вступ каже, що джерела доступні на сайті. Перемикачі в `config/editorial.json`: `spoken_attribution` (назва видання на початку сюжету), `spoken_coverage` (перелік інших видань). Відкидаються: заголовки-питання, «мітки» («Reuters: …»), фрагменти («, який …»), фонові речення («Нагадаємо…»), мета-атрибуція («Про це йдеться…»). Це прибирає проблему Gemini (вільний переказ, слова-паразити) повністю: у тексті немає слів, яких не опублікувало джерело.
*Ціна:* текст звучить як стрічка заголовків, а не як авторський випуск. Подальше покращення — обмежене редагування (див. «Бажані»), але тільки з тим самим трасуванням фактів.

**Персоналізація без генерації аудіо на користувача.** Озвучуються сегменти (вступ, кожен сюжет, регіональні блоки) один раз на день; плеєр збирає плейлист: обов'язкові новини → обрані теми → решта → [заставка] → блок обраного регіону або загальний огляд регіонів. Вартість TTS не залежить від кількості слухачів.

**Важливість (тестові ваги, `config/editorial.json`).** `importance = 0.25·підтвердження + 0.25·суспільна значущість + 0.15·масштаб + 0.15·актуальність + 0.10·географічна релевантність + 0.10·новизна`. Підтвердження = кількість незалежних видань у кластері; значущість і масштаб — прозорі словники маркерів; актуальність — напіврозпад 10 год; новизна знижується, якщо подія вже була в учорашній чернетці. Популярність не враховується.

**Регіон.** Сюжет потрапляє в регіональний блок, лише якщо регіон названо в заголовку принаймні одного матеріалу і щонайменше в половині матеріалів кластера (інакше вулиця Богдана Хмельницького в Черкасах тягнула сюжет у «Хмельниччину»).

## План

**Обов'язкові для MVP (зроблено в цьому PR, крім позначених)**
- збір з усіх доступних фідів, злиття пулу, дедуплікація, кластеризація, ранжування;
- екстрактивний сценарій з трасуванням фактів; сторінка редактора; затвердження з sha256;
- модуль TTS з кількома постачальниками; монтаж; ASR-перевірка; публікація з fail-closed;
- інтерфейс: теми, регіон, плеєр, першоджерела, список медіа;
- ⏳ *рішення:* вибір TTS (після прослуховування), погодження ваг і пілотних регіонів, місце зберігання аудіо.

**Бажані**
- словник вимови після прослуховування (наголоси, прізвища, абревіатури);
- обмежене скорочення речень редактором прямо на сторінці перевірки — є; автоматичне скорочення — лише якщо зберігається перевірка «кожне число/ім'я є в джерелі»;
- запит офіційних фідів у Суспільного, hromadske, Frontliner та регіональних редакцій без RSS (листи від редакції — не технічний обхід);
- метрики: дослуховування, переходи до першоджерел (без персональних даних).

**Відкладені**
- автоматична публікація без редактора;
- «Запитайте BRIEF» (відповіді лише з корпусу з посиланнями);
- персональні голосові випуски, платні функції.

## Орієнтовні витрати

Обсяг тексту для TTS за реальною чернеткою 20.10.2026: **≈5 900 символів/день** (національний блок, огляд регіонів і 3 пілотні регіони) → ≈180 тис. символів/місяць. Усі 24 регіони + Крим ≈ 1,3 млн символів/місяць.

| TTS | Ціна (офіційна, перевірено 20.10.2026) | 3 пілотні регіони (~0,18 млн/міс) | Усі регіони (~1,3 млн/міс) |
|---|---|---|---|
| Piper (локально) | $0 | $0 | $0 |
| Google Chirp 3 HD | $30 / 1 млн, перший 1 млн/міс безкоштовно | $0 (у межах free tier) | ≈ $9 |
| Azure Neural | $15 / 1 млн, 0,5 млн/міс безкоштовно (F0) | $0 (у межах F0) | ≈ $12 |
| OpenAI tts-1 / tts-1-hd | $15 / $30 за 1 млн; gpt-4o-mini-tts — оплата за токени ($0.60/1 млн текст + $12/1 млн аудіо) | ≈ $2.7 / $5.4 | ≈ $20 / $39 |
| ElevenLabs Multilingual v2 | $0.08 / 1 тис. (pay-as-you-go); Creator $22/міс — 275 тис. | ≈ $14 або тариф Creator $22 | ≈ $100+ (тариф Pro $99 — 1,24 млн) |

**Ухвалені рішення (21.10.2026):** заставки згенеровані командою в Suno на безкоштовному тарифі — можна використовувати, доки сервіс некомерційний (перед будь-якою монетизацією їх треба перегенерувати на платному тарифі або замінити); чернетки й сирі пули лишаються публічними; випуски (аудіо, текст, чернетки) старші за 7 днів видаляються автоматично (`brief prune`, у щоденному workflow і після публікації). Якщо найсвіжіший випуск старший за тиждень, він теж видаляється, і сайт показує заглушку до наступного випуску.

Інфраструктура: GitHub Actions для публічних репозиторіїв — безкоштовно; GitHub Pages — безкоштовно (м'які ліміти: сайт до 1 ГБ, 100 ГБ трафіку/міс). **Аудіо в git**: ~5 МБ/день (64 kbps моно, сегменти + повний файл) ≈ 150 МБ/міс → ліміт Pages буде досягнуто за ~6 місяців. Вирішено: зберігати лише останні 7 днів (≈35 МБ на сайті). Історія git при цьому все одно зростає (~150 МБ/міс); якщо репозиторій стане завеликим — перенести аудіо в зовнішнє сховище.
