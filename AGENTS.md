## 4. Архітектура (коротко; повністю — `docs/ARCHITECTURE.md`)

Python-пакет `brief/`, CLI `python -m brief <команда>`:

```
collect → draft (cluster, score, edition.build, factcheck) → check → approve → render (TTS) → verify-audio (ASR) → publish → prune
                                                                                             ↘ demo (зберегти як демо)
```

- `collect.py`, `normalize.py`, `cluster.py`, `score.py`, `classify.py` — збір RSS, дедуплікація, ранжування.
- `edition.py` — сценарій: вступ, національний блок, перехід, регіони, нагадування, завершення.
  Сюжет починається з **ліду (першого абзацу)**, не з заголовка; ключові сюжети — ще й другий абзац.
  Назву медіа озвучуємо лише для ексклюзивів/цитованих національних матеріалів; посередині — одне
  нагадування, що всі джерела на сайті.
- `factcheck.py`, `review.py`, `verify.py`, `textmatch.py` — перевірка, що кожне речення є в джерелі;
  `approval_mode: "auto"` відкидає сюжети, які потребують редактора.
- `speech.py` — текст для озвучення: числа словами з відмінками/родом, дати, дроби, лексикон
  (`config/lexicon.json`), наголоси (`config/stress.json` + словник `ukrainian-word-stress`).
- `render.py`, `audio.py` — синтез по реченнях із кешем, паузи (1300 мс між сюжетами), ffmpeg-фільтри
  темпу/висоти для кожного голосу, чергування голосів по сюжетах.
- `tts/` — провайдери: `styletts2` (безкоштовний, локальний), `elevenlabs` (платний, найкраща якість),
  `piper`, `google`, `azure`, `openai`, `mock`.
- `demo.py` — копіює готовий перевірений випуск у `demo/` + `demo/index.json` (не видаляється prune).
- `audition.py`, `publish_audition.py` — **окремий шлях 30.10**: озвучення вручну адаптованого
  сценарію `docs/tts/brief-2026-10-29.json` (Yevhen/Yaroslava) і публікація.

Конфіг: `config/editorial.json` (структура випуску, шаблони фраз, голоси), `config/sources.json`,
`config/regions.json`, `config/media_map.json`, `config/lexicon.json`, `config/stress.json`.

Фронтенд: статичні `index.html` (головна, теми, джерела), `demo.html` (плеєр + текст + джерела),
`review.html` (редакторський перегляд). Без збірки.

## 6. Редакційні правила (повністю — `EDITORIAL.md`, `docs/THEMATIC_NEWS_AND_TEASERS.md`)

- Вступ: «Це BRIEF. Головне за [дата]: [2–3 теми]» — без розкриття подробиць, без сенсаційності.
- Однотипні новини (напр. наслідки ударів у різних містах) можна об'єднувати в один сюжет, його
  читає один диктор. **Сумарні цифри — лише за повністю перевіреною сумою** (5 умов у документі);
  інакше перелічуємо міста без загального числа.
- «Сьогодні/вчора» мають відповідати даті випуску, а не часу генерації.
- Відома проблема ранжування: поодинокий некролог іноді вище за масовану атаку — ще не виправлено.

## 7. GitHub Actions і секрети

| Workflow | Призначення |
|---|---|
| `collect-news.yml` | щогодинний збір новин |
| `draft-edition.yml` | повний безкоштовний випуск (StyleTTS2), **лише вручну** |
| `approve-render.yml`, `render-audio.yml` | ручне затвердження й озвучення |
| `demo-edition.yml` | платне демо: inputs date, provider, model, tempo, service_tempo, service_pitch, stress, alternate, `confirm_paid` |
| `brief-publish-2026-10-29.yml` | одноразова публікація 29.10 (тригер `.github/brief-audio-publish-trigger.txt`) |
| `brief-audio-restore.yml` | відновлення вже оплаченого аудіо з артефакту, без нових запитів |
| `compare-tts.yml`, `tts-ab.yml` | порівняння голосів / A/B наголосів |
| `deploy-pages.yml` | деплой сайту (весь репозиторій) |
| `refresh-registry.yml` | щомісячне оновлення реєстру медіа |
| `ci.yml` | тести |

Секрети/змінні (значення не знаєш і не потребуєш): `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`,
`ELEVENLABS_SERVICE_VOICE_ID` (є і як secret, і як variable — workflow читає `vars.X || secrets.X`),
`BRIEF_MAX_TTS_USD`, опційно `GOOGLE_TTS_CREDENTIALS`, `AZURE_SPEECH_KEY`/`AZURE_SPEECH_REGION`,
`OPENAI_API_KEY`. Ключ ElevenLabs — з мінімальними правами (Text to Speech: Access, Voices: Read).

Особливості: `workflow_dispatch` працює лише для workflow, що вже є в `main`; кеші прив'язані до гілки.

## 8. Як працювати

```bash
pip install -r requirements.txt -r requirements-dev.txt   # + requirements-styletts2.txt для StyleTTS2
python -m pytest -q
python -m brief draft --date 2026-10-29
python -m brief render --date 2026-10-29 --provider mock   # безкоштовна перевірка без реального TTS
```

- Робота — у гілці + PR; не пуш у `main` напряму (крім того, що роблять самі workflow-боти).
- Не force-push і не rebase чужих комітів.
- Перш ніж щось замінювати на сайті — перевір, що на головній лишається один плеєр.
- Коли треба витратити кредити — спершу оцінка (символи, $) і явна згода власника.
